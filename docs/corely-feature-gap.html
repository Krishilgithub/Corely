Corely feature gap

Written 2026-10-21 · Based on the code on branch master and the business scope agreed in our product discussion.

This page compares what Corely needs in order to be sold as "your company's memory, with answers you can trust" with what the code actually does today. Each gap has a status, a priority and a size. The page ends with a phased plan to close the gaps.

The short version. The basic "connect tools and ask questions" flow works for Notion, Google Drive, Gmail and GitHub. But Corely is not ready to sell. It has security holes, two connectors that never become searchable, and permissions that don't restrict anything. The website also claims things that don't exist yet.

The features that would make Corely different from Glean and others are almost all missing: automatic decision memory, stale-knowledge alerts, weekly digests, the learning loop and a Slack bot.

The scope we agreed

These are the decisions from our product discussion. Every gap below is measured against them.

AreaWhat we decided
PositioningNot "enterprise search" (Glean's ground). Corely is enterprise memory: it remembers what the company decided and why, and tells you when knowledge is out of date.
Ideal customer50–1,000 employees, tech or tech-enabled, already on Slack plus Notion or Drive plus GitHub or Linear. The buyer is the Head of Operations, CTO, VP Engineering or Head of People.
Core productConnect sources, then ask with citations and freshness. Organisational memory (decisions, facts). Weekly digest and stale-knowledge alerts. A Slack bot. Admin controls: permissions, audit log, SSO.
MoatMemory that builds up per customer. A learning loop from feedback. Living inside Slack and Teams. A niche focus. Self-hosted or EU-hosted options.
ConnectorsIn order: HubSpot, then Jira and Confluence, then Microsoft 365, then meeting transcripts, then Zendesk or Intercom, then Salesforce. LinkedIn and X are not core; maybe one "company mentions" add-on later.
CommercialFree tier, then a per-seat team plan, then an Enterprise plan (SSO, audit, self-hosting, data residency). Paid pilots with measured results.
Out of scopeProject management, a CRM, a general chatbot, and autonomous agents that take actions in other tools (until they exist, remove the claims).

Implementation plan

The plan follows the business order. First make it safe to sell, then make the answers trustworthy, then build the moat. After that, meet people where they work, add the connectors the ideal customer needs, and finally make it enterprise-ready. Estimates assume one full-time developer. With two developers, Phases 3–5 can run in parallel.

Risks and open decisions

Risk or decisionWhat to do
The website claims SOC 2 Type II, SSO/SAML, Claude 3.5, a Jira connector and autonomous agentsRemove the claims in Phase 0. Add each one back only when it is true. A false SOC 2 claim is a legal risk.
Competitors (Glean, Onyx, Supermemory, Coworker AI, ZeroForget AI) already cover "connect and ask"Don't compete on search. Ship the Phase 2 memory features first and lead every demo with them.
Decision extraction costs money (one LLM call per new document)Run it only on new or changed content. Use a small, cheap model to sort content and the main model only for real decisions. Set a monthly cost cap per workspace.
Microsoft Teams messages may need tenant-admin consentStart Microsoft 365 with Outlook, OneDrive and SharePoint. Add Teams when a pilot customer's IT team can give consent.
Sync runs inside the web request todayMove to the BullMQ worker in Phase 1, before adding more connectors. Otherwise big syncs time out on serverless hosting.
LinkedIn and X APIs are restricted or paidKeep them out of the core product. Revisit only if pilots ask for "company mentions".
