One question, step by step

What happens when you ask

1

Check access. Valid session, the user’s workspace, and a limit of 20 questions a minute.

2

Embed the question into 1536 numbers with the same model used for documents.

3

Search pgvector for the 8 closest chunks above 0.55, only from sources this user may see.

4

Score freshness for each source: chat loses 2 points a day, documents 0.2.

5

Claude streams the answer with [1], [2] citations, written only from those chunks.

6

Save and confirm. The answer is stored, and its id is sent so feedback works.

Vector search (simplified)

SELECT content, metadata,
  1 - (embedding <=> $q) AS score
FROM document_chunks
WHERE source_id = ANY($allowed)
  AND 1 - (embedding <=> $q) > 0.55
ORDER BY embedding <=> $q
LIMIT 8;

Click through the six steps of one question. One: the server checks the session and workspace, and limits each user to 20 questions a minute. Two: the question is turned into 1536 numbers with the same embedding model used for the documents, so they can be compared. Three: pgvector finds the 8 closest chunks; the score is one minus the cosine distance, and anything at or below 0.55 is dropped. Only sources the user is allowed to see are searched. Four: each source gets a freshness score; chat goes stale fastest. Five: Claude writes the answer only from those chunks, with numbered citations, and it streams to the browser as Server-Sent Events: first the sources, then the text, then the saved message id, then done. Six: the answer is saved to the chat history. If no chunk passes 0.55, Corely replies that it does not know, without calling the model at all.
