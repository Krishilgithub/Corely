The six tables behind every answer

Source

A connected tool: type, status, encrypted OAuth tokens, last sync

Document

One item: title, link, content hash, and where it lives (channel, page, folder, repo)

DocumentChunk

About 400 words of text plus a vector(1536) for cosine search

Project

Name, short key, other names, status and phase

DocumentProject

How a document joined: linked, name rule, AI or manual. Manual choices win.

OrgMemory

Decision, risk, milestone, question or fact, linked to its project and source

These are the six tables that matter most; there are more for users, roles, teams and chats. A source is one connected tool, and its OAuth tokens are stored encrypted with AES. Each source has many documents; a content hash lets a sync skip anything that has not changed. Each document is split into chunks of about 400 words, and each chunk stores a vector of 1536 numbers that pgvector searches by cosine similarity, which is why it is highlighted. Projects link to documents through DocumentProject, which records how the match was made: a linked source first, then a name rule, then AI, then a person. A person’s choice is never overwritten. Finally, OrgMemory holds the decisions, risks, milestones, questions and facts, each linked to its project and to the document it came from. Every table also has a workspace id, which keeps each company’s data apart.
