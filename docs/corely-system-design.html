Corely System Design

How Corely is built today, which tools it uses, where the weak spots are, and where it could go next.

Source: a read-only audit of C:\dev\Corely, branch master, commit 14a5dc5. Every claim points to a file. "Today" means the code as it is, not the plans in the root *.md files.

Correction to CLAUDE.md. CLAUDE.md says every connector purges deleted items and wraps provider calls in withRetry. In the code, only modules/sources/connectors/notion.ts does both (withRetry at line 375, purge at lines 129-147). The other five connectors do neither.

1. Overview

Corely is a web app that acts as a company's "institutional memory". It connects to the tools a team already uses, reads their content, and lets people ask questions about it in plain language. Answers come back with citations and a note on how fresh the source is.

Under the hood it is a RAG app (retrieval-augmented generation: find the relevant text first, then ask a language model to answer using only that text). It is built with Next.js 15 App Router, Postgres with the pgvector extension (stores and searches number vectors), and OpenAI.

Main users

Core use cases

  1. Connect a source. OAuth into Notion, Gmail, Google Drive, GitHub, Slack or Linear, or upload a file (PDF, DOCX, plain text).
  2. Sync and index. Pull content, split it into chunks, turn each chunk into an embedding (a list of 1536 numbers that captures meaning), and store it.
  3. Ask Corely. Ask a question. Corely finds the closest chunks, scores their freshness, and streams a gpt-4o answer with sources. Chats are saved as sessions.
  4. Search. POST /api/search returns matching chunks without an AI answer.
  5. Workspace admin. Teams, roles, API keys, notifications, settings, org memory, workflows and insights. Several of these are partly fake or simulated today (see API surface).

2. High-level architecture

Corely is one Next.js app. The same Node process serves the marketing pages, the dashboard, all API routes, and also runs source syncs in the background. Postgres (hosted on Supabase) is the only database. Redis is optional.

4. Request flow

Almost every dashboard page is a client component ("use client"). It calls fetch('/api/...'). The browser sends the corely_session cookie on its own. The route handler checks who the user is, does its work, and returns one standard JSON shape.

The pieces

  • Envelope. successResponse(data, status = 200) and errorResponse(message, status = 500) in lib/api-response.ts wrap every answer as { success, data | error, version: "v1" }. A few routes skip it and return plain JSON: /api/context-stats, /api/sources/[sourceId]/github/repos, and the 401 branch of the OAuth connect routes. /api/ask returns text/event-stream instead.
  • auth(). Reads the corely_session cookie, checks it with jose (HS256, key from JWT_SECRET), checks that userId and workspaceId are strings, then loads the user with workspace and workspaceRole. If an admin user has no roleId, it finds the workspace's "Admin" role and saves it ("auto-heal"). Returns { user, workspace }.
  • requirePermission(p). Calls auth(), then throws "Forbidden: Insufficient permissions" unless user.workspaceRole.permissions contains p. Only 7 route files use it: insights, memory, sources (GET), teams, teams/[id], teams/members, teams/[id]/members/[memberId].
  • force-dynamic. export const dynamic = "force-dynamic" tells Next.js to run the handler on every request and never pre-render it at build time. It is set on most auth or streaming routes, but not all (for example context-stats, notifications, teams, workflows, users/me, search do not set it). Those still run per request because they read cookies, which makes them dynamic.
  • Server component path. app/dashboard/page.tsx is the exception. It calls auth() and prisma directly on the server and passes data to DashboardClient.tsx.
  • No middleware. There is no middleware.ts. The dashboard is only guarded by a client-side redirect in app/lib/auth-context.tsx (lines 65-70) and by each API route's own checks.

5. Data model

prisma/schema.prisma defines 18 models. Every model except Workspace itself and ChatMessage has a workspace_id that points to Workspace with onDelete: Cascade. Deleting a workspace deletes everything in it. All ids are UUIDs with the database default uuid_generate_v4().

Groups of models

  • Identity: Workspace, User, WorkspaceRole, Team (many-to-many with users), ApiKey, AuditLog, Notification.
  • Ingestion: Source → Document → DocumentChunk. Dedupe uses Document.contentHash. @@unique([sourceId, externalId]) stops the same upstream item being stored twice.
  • Chat: ChatSession → ChatMessage. Sessions have no userId, so every chat is visible to the whole workspace.
  • Dashboard surfaces: OrgMemory, MemorySnapshot, DashboardInsight, DashboardAction, Workflow, WorkflowActivity. Many fields are display styling (iconBg, healthColor, ownerBg), which shows these tables were shaped around mock UI.

Two clients, one database

Two different clients talk to the same Postgres tables:

  • Prisma (lib/db.ts) connects with DATABASE_URL through a pg Pool and PrismaPg adapter. It is a singleton cached on globalThis outside production. It handles all normal rows.
  • supabaseAdmin (lib/supabase.ts) uses the Supabase REST API with the service-role key (full access, skips row-level security). It exists because Prisma marks embedding as Unsupported("vector") and cannot write it.

Rule: anything that writes an embedding goes through supabaseAdmin. Anything that reads embeddings for search uses raw SQL through prisma.$queryRaw (app/api/ask/route.ts, app/api/search/route.ts).

Bug that breaks two connectors. slack.ts (lines 243-251) and linear.ts (lines 244-252) first create the chunk with prisma.documentChunk.create(), then supabaseAdmin.insert() a row with the same id. The second insert fails on the primary key and the error is only logged. Those rows keep embedding = NULL, so search never finds Slack or Linear content. Gmail, Drive, GitHub and Notion do one supabaseAdmin insert with the embedding, which works.

The vector column (scripts/init-pgvector.ts)

prisma db push skips the embedding column. You must run npx tsx scripts/init-pgvector.ts once per database. It does four things:

  1. CREATE EXTENSION IF NOT EXISTS vector;
  2. Adds document_chunks.embedding vector(1536) if the column is missing.
  3. Creates the HNSW index (a graph index for fast nearest-neighbour search): idx_chunks_embedding ... USING hnsw (embedding vector_cosine_ops) WITH (m = 16, ef_construction = 64). If that fails (pgvector older than 0.5.0), it falls back to an ivfflat index (a cluster-based index): idx_chunks_embedding_ivfflat ... WITH (lists = 100).
  4. Defines match_chunks(query_embedding vector(1536), workspace_filter UUID, match_threshold FLOAT DEFAULT 0.6, match_count INT DEFAULT 5). It returns chunks with 1 - (embedding <=> query) as similarity. Nothing calls it. It also has no source filter, so it would ignore permissions if used.

Two watch items: the schema also declares @@index([embedding], map: "idx_chunks_embedding"), the same index name the script uses. And the UUID default uuid_generate_v4() needs the uuid-ossp extension. Supabase turns it on by default; a plain Postgres would need it added by hand.

7. Auth and security design

Login flow

OAuth connect and callback flow

Scopes are read-only where the provider allows it. For example Google Drive asks for drive.readonly, documents.readonly, spreadsheets.readonly, userinfo.profile and userinfo.email, with access_type: "offline" and prompt: "consent" so a refresh token comes back.

RBAC model

RBAC (role-based access control: rights are given to roles, and users get a role). lib/rbac.ts defines 8 permission strings and 4 default roles. createDefaultRolesForWorkspace() and POST /api/auth/register create the roles per workspace. A role's permissions is a JSON array on WorkspaceRole. hasPermission(), hasAllPermissions() and hasAnyPermission() check it. On the client, AuthProvider exposes hasPermission().

PermissionAdminDeveloperProduct ManagerViewer
memory:readyesyesyesyes

Gaps in the model. There are no permissions for settings, API keys, roles, workflows or upload, so those routes only call auth(). sources:write and insights:write are never checked by any route. And because every role has sources:read, the "permission-aware" source filter in /api/ask (line 146) and /api/search (line 54) lets everyone search every source.

Token encryption

  • lib/crypto.ts calls CryptoJS.AES.encrypt(text, ENCRYPTION_KEY). Passing a string key puts crypto-js in passphrase mode: it derives the key with EVP_BytesToKey (MD5, 1 round), uses AES-CBC, and adds no MAC (no tamper check).
  • decrypt() returns an empty string on a wrong key instead of throwing.
  • ENCRYPTION_KEY is the only secret with no fallback: getKey() throws if it is missing.
  • Stored fields: Source.accessToken and Source.refreshToken.

Cookie flags

Set the same way in login/route.ts and register/route.ts: name corely_session, httpOnly: true, secure: process.env.NODE_ENV === "production", sameSite: "lax", maxAge: 86400 (24 hours), path: "/". "Remember me" in the UI is never sent, so every session lasts exactly 24 hours. Logout only deletes the cookie; a stolen token stays valid until it expires.

8. Ingestion and retrieval

This is a short summary. For the full detail, including per-connector limits and prompt design, read AI Pipelines.

  • Ingestion triggers. POST /api/sources/[sourceId]/sync (fire-and-forget dynamic import()), the Gmail and Notion OAuth callbacks, POST /api/sources/upload, and POST /api/documents. No schedule, no working webhooks, and the BullMQ queue is never used.
  • Known breaks. Slack and Linear chunks never get embeddings. Only Notion purges deleted items. Gmail takes only the newest 100 threads from the last 180 days and never runs its incremental path. Freshness uses Document.updatedAt, which is @updatedAt (index time), so most sources look fresh after every sync.
  • Embedding model fallback. lib/openai.ts silently falls back from text-embedding-3-small to text-embedding-ada-002. Both return 1536 numbers, but they are different vector spaces. Mixing them ruins similarity scores.
  • Hallucination guard. When no chunk clears 0.55, the route sends a fixed "no knowledge" answer and never calls the model. Keep this.

Vercel hints

  • https://corely-khaki.vercel.app is hardcoded twice: the reset-link fallback (app/api/auth/forgot-password/route.ts:38) and the invite email login button (app/api/teams/members/route.ts:81). Invites from any other deployment point people to that URL.

  • There is no vercel.json, no cron config and no function duration setting.
  • On Vercel, each API route runs as a serverless function. Long syncs will likely die halfway and leave the source stuck on "syncing". Docker does not have this problem because the Node process stays up.

10. Non-functional review

Honest notes on the current state, with fixes taken from the implementation plan in the gap analysis.

Scalability

Now

  • Embeddings are made one chunk at a time, in series, with one OpenAI call each. A 4,000-word document is about 11 chunks, so 11 round trips.
  • Syncs run inside the web process. Heavy syncs compete with user requests.
  • Login and fallback rate limits are per process, so they do not hold across instances.
  • Gmail caps at 100 threads; Slack at 500 messages per channel and 200 channels; GitHub at README + 100 issues + 50 PRs.
  • Each process has its own pg Pool. Many serverless instances can exhaust Postgres connections.

Recommend

  • Batch embeddings (the API takes an array of inputs).
  • Enqueue to sourceQueue and run the worker as a second compose service.
  • Use a pooled connection string (Supabase pooler) for serverless.
  • Move all rate limits to Redis.

Performance

Now

  • Retrieval is one indexed vector query (LIMIT 8) plus three source-list queries per question.
  • /api/analytics loads every document's rawContent into memory to count bytes.
  • A changed document has all its chunks deleted and embedded again.
  • The Docker image is about 2.6 GB because it keeps dev dependencies and source files.

Recommend

  • Compute storage with SUM(octet_length(raw_content)) in SQL.
  • Move @prisma/adapter-pg, pg and tsx to dependencies, then npm ci --omit=dev in the runner stage.
  • Remove unused packages (ai, docx, gsap, 4 Radix packages, class-variance-authority, cross-env).

Reliability

Now

  • Fire-and-forget sync: on serverless it can be cut off after the response.
  • Connectors throw early errors (no token, refresh failure, "Gmail OAuth is not configured") before their try block, so status stays "syncing" forever and retries get 409.
  • Only Notion has withRetry (401 → reconnect, 429 → backoff). BullMQ's 3 attempts with backoff are unused.
  • Slack and Linear chunks fail to insert, and the error is only logged.
  • No root error.tsx, global-error.tsx or not-found.tsx; only app/dashboard/error.tsx.
  • No migrations: db push only, no history, no rollback.

Recommend

  • Wrap each connector body in try/catch that sets status "error"; recover stale "syncing" rows.
  • Shared withRetry for all connectors.
  • Switch to prisma migrate and add zod env validation that fails fast.

Observability

Now

  • Only console.log / console.error, often with emoji. No logger, no request ids, no Sentry.
  • Audit log is written only on password change; ipAddress is never set.
  • Sync history is one synthetic entry; there is no record of real runs.
  • The compose healthcheck only fetches /; it does not check the database.
  • No tests and no CI.

Recommend

  • Add Sentry and a structured logger to the app and worker.
  • Write a sync-history row per run; notify on sync failure.
  • Audit logins, invites, role changes, source connect/sync and key creation.
  • Vitest plus a GitHub Actions workflow for lint, type check and tests.

Security

Now

  • Leaked SMTP password in git; 9 unauthenticated route handlers; login takeover; unsafe JWT fallback; state token reuse risk; weak token crypto. Full list in the threat list.
  • No middleware, no security headers, no rate limits on register, forgot-password, search or upload.

Recommend

  • Phase 0 first: rotate the Gmail password, remove fallback secrets, add auth and workspace checks to the open routes, add middleware.ts, remove the no-password login path and _devPassword, use a separate key for OAuth state and check the nonce.
  • Replace crypto-js with Node crypto AES-256-GCM and re-encrypt tokens.
  • Add permissions for settings, API keys, roles and workflows; narrow Viewer.

Cost

Now

  • Every answered question is a gpt-4o call with up to 8 chunks of about 400 words, 6 history messages, and up to 1,500 output tokens.
  • Questions with no match cost only one embedding call (the no-knowledge guard).
  • Re-embedding whole documents on any change multiplies embedding spend.
  • Plan limits (100 docs / 500 queries) are shown but not enforced, and the plan never changes from "trial".

Recommend

  • Honour the saved defaultLlm so cheaper models can be used.
  • Enforce limits per plan; add Stripe to tie usage to billing.
  • Incremental sync (Gmail history.list, Drive changes.list, Slack oldest, Linear updatedAt) to avoid re-reading everything.

12. Glossary

App Router
The Next.js way of building pages and APIs from folders under app/. A page.tsx is a page; a route.ts is an API endpoint.
Route handler
A route.ts file that exports functions named after HTTP methods (GET, POST and so on).
Server component / client component
A server component runs only on the server and can read the database directly. A client component ("use client") runs in the browser and must call APIs.
force-dynamic
A route setting that makes Next.js run the code on every request instead of caching a pre-built result.
Middleware
A middleware.ts file that runs before matching requests, often used to redirect people who are not logged in. Corely has none.
RAG (retrieval-augmented generation)
Find relevant text first, then give it to a language model so the answer is based on that text.
Embedding
A list of numbers (1536 here) that stands for the meaning of a piece of text. Similar meanings give nearby lists.
Chunk
A slice of a document (400 words with 50 words of overlap in Corely) that gets its own embedding.
pgvector
A Postgres extension that adds a vector column type and distance operators such as <=> (cosine distance).
Cosine similarity
A score from -1 to 1 of how closely two vectors point the same way. Corely uses 1 - cosine distance and keeps chunks above 0.55.
HNSW / ivfflat
Two index types for fast "find the nearest vectors" search. HNSW builds a layered graph; ivfflat groups vectors into clusters (lists).
SSE (server-sent events)
A simple one-way stream from server to browser over HTTP, sent as data: ... lines. /api/ask uses it to stream the answer.
JWT (JSON Web Token)
A signed, base64-encoded JSON object. Anyone with the key can check it was not changed.
HS256
A JWT signing method that uses one shared secret (HMAC with SHA-256).
OAuth
A standard that lets a user give Corely limited access to another service without sharing their password.
OAuth state
A value sent to the provider and returned in the callback, used to tie the callback to the user who started it and stop forged callbacks.
Nonce
A random one-time value. It only protects anything if the server saves it and checks it later.
RBAC (role-based access control)
Rights are given to roles, and each user gets a role.
Envelope
The fixed JSON wrapper every API answer uses: { success, data | error, version }.
Prisma
A TypeScript database toolkit: schema file, generated client, and schema push or migrations.
db push vs migrations
db push changes the live database to match the schema with no history. Migrations are saved SQL steps you can review, replay and roll back.
Service-role key
A Supabase key with full database access that skips row-level security. Server only.
BullMQ
A job queue for Node that stores jobs in Redis and runs them in worker processes, with retries and schedules.
Redis
A fast in-memory data store. Corely uses it for rate-limit counters and (unused) the job queue.
Fire-and-forget
Starting work and returning without waiting for it or tracking its result.
Serverless function
Code that a platform such as Vercel starts per request and may freeze or stop soon after the response is sent.
Hybrid search
Combining keyword search (Postgres tsvector) with vector search, so exact names and codes are found as well as similar meanings.
AES-CBC / AES-GCM
Two ways to use AES encryption. CBC alone does not detect tampering; GCM does, because it adds an authentication tag.
EVP_BytesToKey
An old OpenSSL method to turn a passphrase into a key. With MD5 and one round, it is fast to brute-force.
bcrypt
A slow password-hashing function. Corely uses cost 10.
Multi-stage Docker build
A Dockerfile with several FROM steps, where later steps copy only what they need from earlier ones.
Healthcheck
A command Docker runs on a timer to decide if a container is healthy.
